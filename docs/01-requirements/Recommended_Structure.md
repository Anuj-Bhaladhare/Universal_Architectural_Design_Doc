### Recommended principle for this document

The **27 points should remain the fixed top-level structure**. Inside each point, you can add or remove sub-sections depending on the project.

For example:

```text
8. Functional Requirements
│
├── 8.1 Authentication
├── 8.2 User Management
├── 8.3 Profile Management
├── 8.4 Feature/Module A
├── 8.5 Feature/Module B
├── 8.6 Notifications
└── 8.7 Reports
```

For another project:

```text
8. Functional Requirements
│
├── 8.1 Student Management
├── 8.2 Bus Management
├── 8.3 Driver Management
├── 8.4 GPS Tracking
├── 8.5 Parent Management
├── 8.6 Notifications
└── 8.7 Attendance
```

So the **27-point framework stays universal**, while the **subsections become project-specific**.

This makes it much better as a reusable master template for **any Web + Mobile project**, rather than tying the document structure to one particular product.
